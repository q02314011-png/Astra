# Astra 0.1.0

Тестовая версия мессенджера **Astra**: вход по номеру телефона с SMS-кодом.
Один код приложения собирается и в **APK** (Android), и в **EXE** (Windows).

Что работает:
- выбор страны и ввод номера телефона
- отправка кода подтверждения
- ввод кода с автоотправкой и таймером повторной отправки
- вход, профиль, смена имени, выход из аккаунта
- **автономный режим**: приложение работает вообще без сервера
- поиск сервера в сети и автопочинка опечаток в адресе
- **переписка с друзьями**: список диалогов, поиск по номеру, отправка и приём
  сообщений в реальном времени, счётчики непрочитанного, галочки прочтения

## Как переписываться с друзьями

Коротко: поднять сервер, зайти в Astra с двух телефонов (или с телефона и компьютера),
найти друга по номеру — и писать.

1. **Поднять сервер.** На компьютере: `node server/src/index.js`, либо запустить
   `Astra-0.1.0-portable.exe` — он поднимет сервер сам. С терминала сервер напечатает
   адрес вроде `http://192.168.0.106:4000` и предложит открыть его в приложении.
2. **Второй человек подключается к тому же серверу.** Android: в настройках указать
   `http://192.168.0.106:4000` (не `127.0.0.1` — это сам телефон; в эмуляторе
   подойдёт `10.0.2.2:4000`). В приложении есть «Найти сервер» — перебирает адреса
   в сети и проверяет, где отвечает Astra. Телефон должен быть в той же Wi-Fi-сети.
3. **Оба входят по своим номерам** (в тестовом режиме код показывается на экране).
4. **«Чаты» → «Новый» → номер друга.** Номер должен совпадать с тем, по которому
   друг вошёл. Если выведет «ещё не зарегистрирован» — значит он ещё не входил.
5. Пишете. Сообщения приходят мгновенно, без перезагрузки и без кнопки «обновить».

Что важно понимать про переписку:

| | |
|---|---|
| Где живут сообщения | на сервере, в его файле базы (`server/data/astra.json`, а у EXE — `%APPDATA%\astra-desktop\data\astra.json`) |
| Видны ли они обоим | да, это общий диалог, а не «отправлено на этом устройстве» |
| Нужен ли интернет | сеть между устройствами: Wi-Fi, LAN или туннель |
| Шифрование | транспортное (HTTP в вашей сети). Сквозного шифрования (E2E) **нет** |
| В автономном режиме | чатов нет — переписка существует только на сервере |

Ограничения, которые важно знать:

- **Сервер должен быть запущен**, пока вы переписываетесь. Это не облачный сервис,
  а программа на компьютере. Компьютер выключили — переписки нет.
- **Чтобы переписываться из дома с работы или из другой сети**, нужен туннель
  (например, cloudflared — см. ниже) или свой хостинг. Без этого два устройства
  должны быть в одной сети.
- **Ограничения на сообщения**: до 4000 символов, история подгружается при прокрутке
  вверх. Картинок, голосовых и звонков пока нет.
- **Офлайн-сообщения не копятся**: если собеседник офлайн, сообщение сохранится,
  но уведомление придёт только когда он снова зайдёт (счётчик обновится при входе).

## Три режима работы

Главное, что стоит понять до запуска: **сервер — это отдельная вещь**, и есть три
варианта, как им пользоваться.

| Режим | Где работает | Что нужно | Когда включать |
|---|---|---|---|
| Свой сервер | на любом ПК или в интернете | запустить сервер Astra | чтобы SMS приходили на реальные номера |
| Автономный | только на устройстве | ничего | проверить интерфейс без сервера |
| Встроенный | внутри EXE на Windows | ничего, EXE уже всё содержит | обычная работа на компьютере |

### 1. EXE на Windows — сервер поднимается сам

`Astra-0.1.0-portable.exe` содержит бэкенд внутри себя. При запуске он:

1. проверяет, не запущен ли уже сервер Astra на порту 4000;
2. если нет — запускает его отдельным процессом тем же Node, что встроен в Electron
   (устанавливать Node не нужно);
3. при закрытии приложения сервер останавливается.

Если сервер не поднялся, приложение всё равно откроется и предложит автономный режим.
Перезапустить сервер вручную: меню **Astra → Перезапустить сервер**.
Данные лежат в `%APPDATA%\Astra\data` — папка установки может быть защищена от записи.

### 2. Телефон на Android — нужен адрес сервера

APK не может запустить сервер внутри себя: на Android нет Node. Поэтому есть два пути.

**Вариант А — локальная сеть.** Сервер запущен на твоём ПК, телефон в той же Wi-Fi сети.

```powershell
# на компьютере
setup\start-server.cmd
```

При старте сервер печатает адрес вида `http://192.168.0.106:4000`. В приложении:
**Настройки → Адрес сервера** → вставь его → **Сохранить и проверить**.

**Вариант Б — сервер в интернете.** Тогда адрес будет вида `https://astra-твой-домен.рф`
и работать откуда угодно. См. раздел [Сервер в интернете](#сервер-в-интернете).

### 3. Автономный режим — сервер не нужен вообще

Если сервера нет, приложение не показывает глухую ошибку, а предлагает выход:

- **Настройки → Работать без сервера**, или
- на экране входа кнопка **Войти без сервера**, когда сервер не найден.

Что работает: вход по номеру, код подтверждения, профиль, смена имени.
Что не работает: SMS не отправляются, аккаунт существует только на этом устройстве,
данные не синхронизируются. Это режим для проверки интерфейса.

Если сервер был, но временно недоступен — приложение не выкидывает на экран входа,
а показывает сохранённый профиль с пометкой «нет связи с сервером». Токен при этом
не сбрасывается: как только сервер вернётся, сессия снова заработает.

## Поиск сервера и опечатки в адресе

Адрес в настройках проверяется и чинится автоматически:

| Ввёл | Приложение использует |
|---|---|
| `127.0.0.01:4000` | `http://127.0.0.1:4000` |
| `192.168.0.106` | `http://192.168.0.106:4000` |
| `htp://127.0.0.1:4000` | `http://127.0.0.1:4000` |
| `htps://astra.example.com` | `https://astra.example.com:4000` |
| `astra.example.com` | `http://astra.example.com:4000` |
| `://127.0.0.1:4000` | `http://127.0.0.1:4000` |
| `999.1.1.1:4000` | отклоняется: «часть 999 больше 255» |
| `просто текст` | отклоняется: «в адресе есть нелатинские символы» |

Кнопка **Найти сервер автоматически** перебирает `127.0.0.1`, `localhost`, `10.0.2.2`
и показывает, какой из них отвечает и за сколько миллисекунд.

## Сервер в интернете

Чтобы приложение работало на чужом телефоне, в другой стране или там, где твоего
компьютера вообще нет, сервер нужно куда-то вынести. Бэкенд не имеет зависимостей
и собирается в Docker-образ одной командой:

Образ собирается из корня репозитория:

```powershell
docker build -t astra-server .
docker run -d -p 4000:4000 -v astra-data:/data --name astra astra-server
```

Бэкенд слушает `0.0.0.0:$PORT`, хранит базу в томе `/data`, отвечает на
`GET /api/health` — этого достаточно для healthcheck хостингов.

Обратный прокси (nginx/Caddy) нужен только для HTTPS и красивого домена.
Обязательно поставь HTTPS: без него токен входа передаётся открытым текстом.

### Railway — самый простой путь

В репозитории лежит `railway.json`, платформа подхватит его сама:

1. Залей репозиторий на GitHub.
2. Открой [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
3. Выбери репозиторий. Railway увидит `railway.json` и `Dockerfile` в корне.
4. После деплоя он даст адрес вида `astra-xxx.up.railway.app`.
5. Этот адрес впиши в приложении: «Настройки → Сервер и вход».
   Поставь галочку **Использовать HTTPS** — Railway сам redirects на `https://`.
6. **Обязательно подключи диск**: в сервисе → **Volumes** → Mount `/data`.
   Без диска чаты и аккаунты будут стираться при каждом перезапуске.

### Честно про границы

Постоянный публичный сервер я за тебя разместить не могу: нужны аккаунт хостинга,
платёжный метод и домен — всё это только твоё, у меня нет к ним доступа.
Проверил доступность из этой сети: `railway.app` и `fly.io` отвечают,
`render.com` и `koyeb.com` заблокированы.

Что можно сделать сразу, без регистраций:

**1. Туннель с твоего компьютера** (сервер живёт, пока включён твой ПК).

```powershell
winget install --id Cloudflare.cloudflared   # один раз
setup\start-server.cmd                       # в одном окне
setup\start-tunnel.cmd                       # в другом
```

Он выдаст адрес вида `https://что-то-случайное.trycloudflare.com` — вставь его
в настройках приложения. Работает сразу, без аккаунта Cloudflare. Минус: адрес
меняется при каждом запуске, и всё падает, когда компьютер выключен.

**2. Свой телефон в той же Wi-Fi сети** — самый надёжный бесплатный вариант.
Сервер на ПК + адрес `http://192.168.x.x:4000` в настройках APK. Интернет для
этого не нужен вообще.

**3. Полноценный хостинг** — Railway, Fly.io, VPS. Там сервер живёт постоянно,
но аккаунт и оплату придётся завести самому.

## Про SMS — важно прочитать

**Бесплатных реальных SMS не существует.** Любой провайдер (5sim, SMS-Activate, Twilio)
берёт оплату за каждое сообщение, и аккаунт с ключом заводится только вручную.

Поэтому в проекте два режима:

| Режим | Что происходит | Стоимость |
|---|---|---|
| `SMS_MODE=dev` (по умолчанию) | Код **показывается на экране приложения**, реальные SMS не отправляются | 0 ₽ |
| `SMS_MODE=real` | Настоящие SMS через провайдера | по тарифу провайдера |

Полный цикл входа (запрос кода → проверка → профиль) в dev-режиме проверяется полностью —
отличается только способ доставки кода.

### Как включить реальные SMS

1. Заведи аккаунт и ключ у одного из провайдеров:
   - [5sim.net](https://5sim.net) — самый стабильный, есть пробный баланс
   - [SMS-Activate](https://sms-activate.org)
   - [Twilio](https://www.twilio.com) — есть официальные бесплатные кредиты новым аккаунтам
2. Открой `server/.env` и поменяй:

   ```ini
   SMS_MODE=real
   SMS_PROVIDER=fivesim        # или sms-activate, или twilio
   FIVESIM_API_KEY=твой_ключ
   ```
3. Перезапусти сервер.

Провайдеры уже реализованы в `server/src/sms/`: `dev.js`, `fivesim.js`, `smsactivate.js`, `twilio.js`.

## Запуск

Самый простой путь: запусти `dist\Astra-0.1.0-portable.exe`. Сервер поднимется сам.

Если нужен отдельный сервер (для телефона на Android или для сервера в интернете):

```powershell
# 1. запустить сервер (оставь окно открытым)
setup\start-server.cmd

# 2. проверить, что он работает
curl http://127.0.0.1:4000/api/health
```

Если порт 4000 занят, сервер скажет об этом и подскажет, что делать. Можно запустить
на другом порту: `PORT=4100 node src/index.js` (тогда в приложении укажи порт 4100).

Проверка, что всё в порядке:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup\test-server.ps1
```

## Готовые сборки

| Файл | Платформа | Размер |
|---|---|---|
| `dist/Astra-0.1.0.apk` | Android 6.0+ | ~0.2 МБ |
| `dist/Astra-0.1.0-x64.exe` | Windows 10+ (установщик) | ~78 МБ |
| `dist/Astra-0.1.0-portable.exe` | Windows 10+ (без установки) | ~78 МБ |

### Установка APK

Скопируй `Astra-0.1.0.apk` на телефон и открой его. Android спросит разрешение
«установка из неизвестных источников» — разреши для файлового менеджера.

### EXE

`Astra-0.1.0-portable.exe` запускается сразу, без установки. Второй файл — установщик
с выбором папки и ярлыками на рабочем столе.

Windows покажет SmartScreen-предупреждение: EXE не подписаны сертификатом,
это нормально для тестовой сборки. Нажми **Подробнее** → **Выполнить в любом случае**.

## Пересборка

```powershell
# только интерфейс
powershell -ExecutionPolicy Bypass -File .\setup\build-web.ps1

# APK (aapt2 + javac + d8 + apksigner, без Gradle)
powershell -ExecutionPolicy Bypass -File .\setup\build-apk.ps1

# EXE
powershell -ExecutionPolicy Bypass -File .\setup\build-exe.ps1

# проверка бэкенда: ASTRA_DATA_DIR, занятый порт, health
powershell -ExecutionPolicy Bypass -File .\setup\test-server.ps1

# проверка чатов на живом сервере: 41 тест, поднимет сервер сам
cd server
node src/index.js --quiet          # в одном окне
node src/selftest-chat.js          # в другом
```

`selftest-chat.js` бьёт по `http://127.0.0.1:4000`; если сервер на другом порту —
задай `ASTRA_TEST_BASE=http://127.0.0.1:4100`.

Перед сборкой EXE закрой запущенный Astra — иначе `electron-builder` не сможет
перезаписать файлы в `desktop\release`. Скрипт закрывает его сам.

### Почему APK собирается без Gradle

В этой сети заблокированы `dl.google.com`, `storage.googleapis.com` и Google Maven,
поэтому Gradle не может разрешить зависимости (`IOException` при определении
зависимостей задачи). Сборка идёт напрямую через инструменты Android SDK:
`aapt2` (ресурсы) → `javac` → `d8` (dex) → `zipalign` → `apksigner` (подпись).
Результат — полноценный подписанный APK, а не обходной вариант.

При этом в `app/android/` лежит обычный Capacitor-проект. Если позже появится
доступ к Google Maven, сборка пойдёт классическим путём: `npx cap sync android` + `gradlew assembleDebug`.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | состояние сервера, режим SMS, статистика |
| GET | `/api/countries` | список стран с кодами |
| POST | `/api/auth/request-code` | запрос кода: `{ phone, country, deviceId }` |
| POST | `/api/auth/verify-code` | проверка кода: `{ phone, code, name }` → `{ token, user }` |
| GET | `/api/me` | профиль (нужен `Authorization: Bearer <token>`) |
| PATCH | `/api/me` | изменить имя и «о себе» |
| POST | `/api/auth/logout` | выход |
| GET | `/api/dev/log` | последние попытки отправки кода (только в dev-режиме) |
| GET | `/api/chats` | список диалогов + `unreadTotal` |
| POST | `/api/chats` | начать переписку: `{ phone, country }` → `{ chat }` |
| GET | `/api/chats/:id` | один диалог |
| GET | `/api/chats/:id/messages` | история: `?limit=&before=` (по метке времени) |
| POST | `/api/chats/:id/messages` | отправить: `{ text }` |
| POST | `/api/chats/:id/read` | отметить прочитанным |
| GET | `/api/contacts/search?q=` | поиск зарегистрированных по номеру |
| GET | `/api/events?token=` | поток событий (newline-delimited JSON) |

Ограничения входа: максимум 5 попыток ввода кода, 8 SMS в час и 30 в сутки на номер,
повторная отправка не раньше чем через 60 секунд.

Формат событий в `/api/events` — по одному JSON-объекту в строке:

```
{"type":"hello","userId":"...","at":1700000000000}
{"type":"message","chatId":"...","message":{"id":"...","text":"...","mine":false,...}}
{"type":"read","chatId":"...","byUserId":"...","at":1700000000000}
{"type":"presence","online":["id-1","id-2"]}
```

У каждого участника своя копия события: поле `mine` показывает, чьё это сообщение
именно для него. Пустые строки — heartbeat, их можно игнорировать.

Готово: вход по номеру, профиль, переписка в реальном времени.
